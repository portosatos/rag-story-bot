# rag-story-bot

Telegram-бот, который отвечает на вопросы по короткому рассказу («Маяк на
мысе Туманном», `data/story.txt`) с помощью RAG: находит релевантные абзацы
через TF-IDF + косинусную близость и передаёт их вместе с вопросом в Claude
для генерации ответа.

## Как это работает

1. `src/rag.py` — рассказ режется на абзацы (`chunk_text`), из них строится
   TF-IDF индекс (`RAGIndex`). `retrieve(query, top_k)` возвращает самые
   похожие на вопрос абзацы.
2. `src/llm.py` — найденные абзацы и вопрос собираются в один промпт
   (`build_prompt`) и отправляются модели Claude (`generate_answer`).
3. `src/bot.py` — Telegram-хендлеры: любое текстовое сообщение
   воспринимается как вопрос, бот ищет контекст и отвечает.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env  # и вписать токены
export $(cat .env | xargs)
python -m src.bot
```

## Тесты и линт

```bash
pytest -v
ruff check .
```

Тесты гоняют `rag.py` и сборку промпта из `llm.py` без обращения к сети —
сам вызов Claude (`generate_answer`) не покрыт юнит-тестом намеренно, это
тонкий wrapper вокруг API, а не логика, которую имеет смысл мокать здесь.

## CI/CD

`.github/workflows/ci.yml` на каждый push/PR в `main` ставит зависимости,
гоняет `ruff check` и `pytest`.

## Как разрабатывалось

Проект сделан как учебное демо: архитектура (разделение retrieval / промпт
/ Telegram-слоя), тексты и тесты написаны с помощью AI-агента (Claude Code)
под моим руководством — я определял структуру модулей, проверял и правил
сгенерированный код (например, дублирующуюся проверку в одном из тестов),
и отвечал за то, чтобы тесты покрывали реальную логику (чанкинг, ранжирование
по score, сборку промпта), а не тривиальные вещи.
